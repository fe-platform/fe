
# Dev Workflow

Isolated MFE development with `fe dev`, hot module replacement via SSE, and the rebuild cycle.

## Starting the Dev Server

```bash
fe dev <mfe-directory>
```

`fe dev` starts a local HTTP server that uses the `JITBundler` adapter logic to compile source on-the-fly. This mirrors the production behavior where the `SourceStorage` adapter provides files to the compiler. Open the URL it prints (typically `http://localhost:3000`) and you see a minimal sandbox page with your MFE rendered into it.

*Note: In this repository, the `sandbox/` folder contains examples of how these paradigms are achieved locally for testing.*

To use a different port:

```bash
fe dev <mfe-directory> 4000
```

## What the Sandbox Serves

The dev server exposes three endpoints:

| Path | Response |
|------|----------|
| `/` | Minimal HTML with an inline import map and a `<div id="sandbox">` |
| `/index.js` | The compiled output of your MFE's `src/index.ts`, generated on request |
| `/__dev` | Server-Sent Events stream for change notifications |

The import map maps your MFE's specifier to `/index.js`. This mapping is generated by the local `ConfigProvider`:

```json
{ "imports": { "fe(@acme/my-mfe)": "/index.js" } }
```

The sandbox page calls `render(container, {})` on page load. You see your MFE.

## Hot Module Replacement

When you save a file in `src/`, the server:

1. Detects the change and invalidates the local JIT cache.
2. Captures the new timestamp in `pendingTs`.
3. Sends `data: {"t": <timestamp>}` over the SSE stream to every connected tab.

The browser handles the notification by:

1. Calling the current unmount function (the return value of the last `render` call).
2. Importing `/index.js?t=<timestamp>`. The cache-busting query parameter forces the browser to treat this as a new module URL, bypassing the native module registry.
3. Calling `render` with the fresh module.

No page reload. No framework-specific hot reload plugin. The `render`/unmount contract is the HMR protocol.

## Reconnecting Tabs

If a tab loses the SSE connection and reconnects (after a network hiccup or sleeping the laptop, for example), the server immediately sends the current `pendingTs` value. The tab imports the latest version from the JIT compiler without missing anything that happened while it was disconnected.

## Limitations of Dev Mode

The dev sandbox's import map only contains your MFE's specifier. If your MFE imports other `fe()` dependencies (as `mfe-b` imports `mfe-a`), those specifiers are not in the map and the browser cannot resolve them.

To develop an MFE that composes others, publish the dependencies to the local storage first and use `fe serve`:

```bash
fe publish <dependency-directory>
fe build shell
fe serve
```

Then edit your primary MFE source and run `fe publish <primary-directory>` each time you want to test the composed result.

*These local steps simulate the global workflow where dependencies are resolved via the `manifest` adapter in `platform.json`.*
